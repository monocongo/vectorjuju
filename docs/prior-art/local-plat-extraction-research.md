# Local extraction options for scanned survey plats

## Question and boundary

Which **local** raster tools are credible for flattened PDF, TIFF, and JPEG plats when the useful output is OCR text with source regions, ordinary table cells, and *candidate* linework—not PDF vector art or a legal/cadastral interpretation?

This is a documentation-only assessment. It did not acquire a corpus, inspect or upload a sample plat, install models or heavyweight packages, or make an accuracy claim. A *source bounding box* below means a region emitted against normalized raster pixels; it is not a survey measurement. A *linework association* means a proposed link between a text/table region and a raster geometry candidate, not a boundary determination.

## Conclusion

Use a raster-only, Mac-first **candidate-evidence** prototype:

1. Render PDF pages with an optional [`pypdfium2`](https://github.com/pypdfium2-team/pypdfium2/blob/main/README.md) adapter; use the already-installed [Pillow](https://github.com/python-pillow/Pillow/blob/main/docs/handbook/image-file-formats.rst) for TIFF/JPEG decode and EXIF-orientation normalization.
2. Use an optional [OcrMac](https://github.com/straussmaximilian/ocrmac/blob/main/README.md) adapter on macOS to emit text, confidence, and normalized image boxes. Use an optional [Tesseract](https://github.com/tesseract-ocr/tesseract/blob/main/doc/tesseract.1.asc) subprocess adapter as the portable fallback.
3. Use an optional [OpenCV](https://github.com/opencv/opencv/blob/4.x/doc/tutorials/imgproc/imgtrans/hough_lines/hough_lines.markdown) sidecar only for raster **geometry candidates** (segments, contours, and fitted primitives).

That is the smallest stack that can preserve a source-to-pixel transform, OCR regions, and inspectable linework candidates without a local model server. It is **not** a line/curve-table or linework-association solution. The smallest documented option that attempts ordinary cell grids is an additional, existing optional Docling/TableFormer adapter; it should be a later experiment, not the first dependency.

## What the current boundary can and cannot preserve

The existing optional Docling adapter is useful evidence that parser selection can be optional, but it is not yet a raster-plat adapter:

- `Parser.parse()` accepts exact **PDF** bytes only; passing a TIFF/JPEG under a changed filename is not a source-media implementation. [`base.py`](https://github.com/monocongo/docproc/blob/d08e508d47b35e6d91d01eb8ed2add16b948877f/src/docproc/adapters/base.py)
- `BBox` is axis-aligned and `BBoxSource` permits only `estimated` or `measured`. The domain definitions mean an OCR detector's inferred pixel region is neither: it is not a document-reported extent, and it is not a font-metric estimate. [`models.py`](https://github.com/monocongo/docproc/blob/d08e508d47b35e6d91d01eb8ed2add16b948877f/src/docproc/models.py), [domain vocabulary](https://github.com/monocongo/docproc/blob/d08e508d47b35e6d91d01eb8ed2add16b948877f/CONTEXT.md#records-and-evidence)
- The Docling adapter converts each provenance box to `(x0, y0, x1, y1)` and retains only dense text cell grids. It therefore cannot retain oriented OCR quadrilaterals, per-cell geometry, or an association edge. [`docling_parser.py`](https://github.com/monocongo/docproc/blob/d08e508d47b35e6d91d01eb8ed2add16b948877f/src/docproc/adapters/docling_parser.py)
- `VisualAnnotation` identifies an embedded image and a caption, but has no region or geometry-candidate channel. A local VLM cannot currently return inspectable proposed associations. [`models.py`](https://github.com/monocongo/docproc/blob/d08e508d47b35e6d91d01eb8ed2add16b948877f/src/docproc/models.py)

Those are evidence-model gaps, not reasons to label raster detections as `measured`. Any later adapter must retain, at minimum: original source digest and media type; page/frame number; normalizer/rasterizer identity and version; pixel dimensions; EXIF/page rotation; crop/scale/affine transform; OCR/model identity; raw region polygon or box; raw recognized text and score; and raw geometry candidate. A Processing Definition must change when any of those behaviorally relevant components changes, consistent with the accepted [Markdown pipeline and evaluation scope](https://github.com/monocongo/docproc/blob/d08e508d47b35e6d91d01eb8ed2add16b948877f/docs/decisions/markdown-pipeline-and-evaluation-scope.md#determinism-and-processing-identity).

## Association rule: deliberately absent

None of the first-party materials above documents a survey-plat interpreter that can establish all of these relations:

- a boundary-call text region to a particular drawn segment or arc;
- a line/curve-table row to a particular boundary segment or curve; or
- a raster curve to a surveyed bearing, distance, radius, delta, or legal boundary.

The first prototype should therefore persist OCR regions and geometric **candidates** separately, with their transforms and raw outputs. At most, a later explicit rule may produce reviewable *association candidates*; it must name its spatial predicate/version and retain both inputs. It must not replace the raw observations, infer a survey measurement from pixels, or claim a correct association without separately authorized evaluation.

## Recommended sequencing

1. **First prototype (small):** PDFium render or Pillow decode → EXIF/page orientation record → OcrMac (Mac) or Tesseract (fallback) → raw OCR-region Artifact; OpenCV produces a separate candidate-geometry Artifact. This has no vector-art dependency, local API call, model server, or table/association claim.
2. **Only if a project-authored synthetic fixture shows the need:** add a Docling source adapter configured with OcrMac and TableFormer to attempt cell grids. Keep it optional: it is heavy, its first-party catalog disables MPS for TableFormer, and its models/license closure require review.
3. **Defer:** RapidOCR until an oriented-polygon/provenance output is designed; a local VLM until a region-bearing Vision schema, local provider adapter, model license review, and a non-authoritative review use case exist.

This stays within the accepted local-prototype boundary: no external corpus, no measured accuracy claim, no cloud deployment, and no claim that the work satisfies a walking vertical or Phase 0 outcome.
